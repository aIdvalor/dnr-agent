Policy decides. The model only gathers. A human confirms.

A tool-calling agent for “delivered but not received” claims. The LLM reads the order, carrier scans and buyer history and drafts the reply. Deterministic code sets eligibility and amount. Nothing is paid until a person clicks Confirm.

Proof of concept. Synthetic orders, scans and buyers. Refunds are simulated entries in a local ledger; no real systems or money. The default model replays a recorded free-tier Gemini run. This page is static: every run is a recording made at build time through the real policy, ledger and commit code, and nothing here calls a model.

      The model has six tools, and none of them can move money.

      1. Readorder · carrier scans · buyer history (scoped to this claim)
      2. check_policydeterministic engine reads source data itself; sets outcome and amount
      3. propose_refundrechecks policy; accepts only the policy amount; pending only
      4. submit_outcomeguard: policy wins, model may only escalate, evidence must have been seen
      5. Human Confirmrechecks again, then one idempotent ledger entry
      Why it is built this way
      • Untrusted text is data. Carrier notes and buyer messages never set an amount; a tripwire only sends instruction-like text to a human.
      • Fail closed. Tool errors, timeouts and inconsistent scans escalate. Escalation is sticky: a later message cannot route around the human.
      • Bounded. 6 steps, 1.5 s per tool, 20 s per step, 60 s per run, temperature 0.
      • Auditable. Every tool call, input, output and latency is shown, not hidden reasoning.

      A proof of concept on synthetic data, not a payment system.

      • One author wrote the policy, the cases, the labels and the 20-case held-out pack, so the held-out pack is not independent; a pack written by someone else is still open.
      • The injection tripwire is a heuristic, not a security boundary: it caught 1 of 4 held-out paraphrases. Amounts, escalation and commit live in code, so a miss costs a human look, not money.
      • The ledger is a single-host file with a lock file: serialized and tested with concurrent processes, but not a distributed system.
      • The live run is one free-tier model for one day of quota (about 1.6 repeats of the pack), so treat its variance as a first look.
      • Single-process file ledger, no auth, no real carrier, store or payment integration.
      • Replay reproduces recorded model responses through today’s code; it cannot show how a model would react to a changed tool result.
